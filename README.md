# ระบบสต็อกสินค้า — มินตรา กรุ๊ป 2019

ยิงบาร์โค้ดตอนรับเข้าและตอนแพ็คส่ง **ยอดขึ้นทุกจอทันที** ฝ่ายขายเปิดหน้านี้แล้วตอบลูกค้าได้เลยว่าของยังมีอีกไหม

> **ไม่ใช่หน้าร้าน** ไม่มีการคิดเงินลูกค้า ไม่มีลิ้นชักเก็บเงิน
> หน้าที่เดียวคือตอบให้ได้ทันทีว่าสินค้าตัวนี้เหลือกี่ชิ้น และของที่เข้าออกคลังตรงกับตัวเลข

**แบบร่างและเหตุผลเบื้องหลังทั้งหมดอยู่ที่ [STOCK.md](STOCK.md)** — อ่านไฟล์นั้นก่อนแก้โค้ด

## แยกขาดจากสมุดบัญชีรายรับรายจ่าย

ระบบนี้กับสมุดบัญชีเป็นสองระบบที่ไม่รู้จักกัน และแยกกันโดยตั้งใจ

| | ระบบสต็อก (รีโปนี้) | สมุดรายรับรายจ่าย (อีกรีโป) |
|---|---|---|
| เก็บอะไร | **จำนวนของ** | **เงิน** |
| Worker | `mintra-stock` | คนละตัว |
| บัญชีผู้ใช้ | `data/users.json` ของรีโปนี้ | คนละไฟล์ คนละชุด |
| cookie | `mintra_stock_session` | คนละชื่อ |
| GitHub token | เขียนได้แค่รีโปนี้ | คนละ token |

ไม่มีปุ่มไหนในระบบนี้เขียนอะไรลงสมุดบัญชี ต้นทุนที่ใส่ที่นี่ใช้คิดมูลค่าสต็อกอย่างเดียว
รายการ "ซื้อสินค้า" ยังลงในสมุดบัญชีด้วยมือตามปกติ

ราคาที่จ่ายไปคือต้องคีย์ยอดซื้อสองที่ และคนที่ใช้ทั้งสองระบบต้องมีสองบัญชี
แลกกับการที่ระบบหนึ่งพังหรือถูกแก้ ไม่มีทางลากอีกระบบไปด้วย

## ใช้งาน

เปิดเว็บ → เข้าสู่ระบบ → แท็บที่เห็นขึ้นกับระดับสิทธิ์ของแต่ละคน

| แท็บ | ใครเห็น | ทำอะไร |
|---|---|---|
| **ดูสต็อก** | ทุกคน | ค้นหา ยิงดู เห็น "พร้อมขาย" เป็นตัวเลขหลัก · จองของ |
| **ยิงสต็อก** | คลังขึ้นไป | รับเข้า · แพ็คส่ง · รับคืน · ย้ายคลัง · ยิงต่อได้ตอนเน็ตหลุด |
| **นับสต็อก** | คลังขึ้นไป | เปิดรอบนับ ยิงนับ รายงานผลต่าง |
| **จอผนังคลัง** | ทุกคน | เอาทีวีเปิดทิ้งไว้ ไม่ต้องกดอะไร |
| **ต้นทุนและมูลค่า** | หัวหน้าคลังขึ้นไป | ใส่ต้นทุนจากบิล · มูลค่าสต็อก · ปรับยอด |
| **สินค้า** | หัวหน้าคลังขึ้นไป | ทะเบียนสินค้า บาร์โค้ด คลัง นำเข้า CSV |
| **พิมพ์ฉลาก** | หัวหน้าคลังขึ้นไป | พิมพ์ฉลากบาร์โค้ด Code 128 ลงสติกเกอร์ |

### ยิงบาร์โค้ดด้วยอะไรได้

| อุปกรณ์ | ใช้ได้ที่ไหน |
|---|---|
| **เครื่องยิง USB/Bluetooth** | ทุกเครื่อง — ทำตัวเป็นคีย์บอร์ด เสียบแล้วยิงได้เลย ไม่ต้องลงไดรเวอร์ |
| **กล้องมือถือ** | ปุ่ม **ยิงด้วยกล้องมือถือ** ในแท็บยิงสต็อก · นับสต็อก · ช่องค้นหาในดูสต็อก |
| **พิมพ์มือ** | ช่องเดียวกัน พิมพ์รหัสหรือชื่อก็ค้นได้ |

**กล้องใช้ได้บน Chrome ของ Android — iPhone ยังไม่รองรับ** เพราะ Safari ไม่มี `BarcodeDetector`
เครื่องที่ใช้ไม่ได้ ระบบซ่อนปุ่มและขึ้นข้อความบอกว่าให้ยิงด้วยเครื่องยิงหรือพิมพ์รหัสแทน

**หนึ่งครั้งกดปุ่ม = หนึ่งการยิง**

```
กดปุ่ม → ส่องบาร์โค้ด → ดัง "ดี้-ด" + สั่น → กล้องปิดเอง เด้งไปที่ผลที่เพิ่งยิง
ยิงชิ้นถัดไป → กดปุ่มใหม่
```

> กล้องปิดทิ้งทันทีที่อ่านติด จำนวนการยิงจึงเท่ากับจำนวนครั้งที่กดปุ่มเสมอ
> ไม่ขึ้นกับว่าถือกล้องค้างนานแค่ไหน — เพราะเวลาที่ถือกล้องค้างไม่ใช่จำนวนของ

### รหัสสินค้าและบาร์โค้ด — ไม่ต้องคิดเอง

เว้นช่องไว้แล้วกดบันทึก ระบบแจกให้

```
รหัสสินค้า   MT-0001, MT-0002 …              คำนำหน้าแก้ได้ในหน้าค่าตั้ง
บาร์โค้ด     2000000000015, 2000000000022 …  13 หลัก ขึ้นต้น 20 พร้อมหลักตรวจสอบ
```

`20`–`29` เป็นช่วงที่มาตรฐาน GS1 สงวนไว้ให้ใช้ในองค์กร จึงไม่ชนกับสินค้าของซัพพลายเออร์รายไหน
และเป็นตัวเลขล้วนเพราะเครื่องยิงทำตัวเป็นคีย์บอร์ด — รหัสที่มีตัวอักษรจะเพี้ยนถ้าคอมตั้งภาษาไทยไว้

**ของที่มีบาร์โค้ดจากโรงงานติดมาแล้ว ยิงลงช่องได้ตามเดิม** ระบบไม่บังคับให้ใช้ของที่มันออกให้
และตัวรันเลขจะข้ามรหัสที่มีคนพิมพ์จองมือไว้ให้เอง

นำเข้า CSV ที่มีแต่คอลัมน์ `name` ก็ได้ ระบบรันรหัสให้ทีละแถว
แถวที่ไม่มีรหัสจะถูกจับคู่กับของเดิม **ด้วยชื่อสินค้า** นำเข้าไฟล์เดิมซ้ำจึงไม่ได้สินค้าคู่แฝด

> เลข 13 หลักกินความกว้างราว 45 มม. — พิมพ์บนสติกเกอร์ 70×37 หรือ 99×57 มม. ได้สบาย
> แต่บนดวง 48×25 มม. ระบบจะเตือนว่าแท่งบางเกินไป ให้ใช้โหมด "ใช้รหัส SKU เสมอ" แทน

## ติดตั้ง

```bash
cd worker
npx wrangler secret put GITHUB_TOKEN      # token ที่เขียนรีโปนี้ได้ (Contents: read & write)
npx wrangler secret put SESSION_SECRET    # ข้อความสุ่มยาว ๆ ใช้เซ็น session
cd .. && ./deploy.sh
```

ครั้งแรกที่เปิดเว็บ ระบบจะให้สร้างบัญชีเจ้าของก่อน — หน้านั้นใช้ได้ครั้งเดียวและปิดตัวเองหลังจากนั้น
Durable Object ถูกสร้างให้เองตอน deploy ครั้งแรก ไม่ต้องตั้งค่าอะไรเพิ่ม

ขั้นตอนถัดไปและวิธีตรวจว่าทำงานถูก อยู่ที่ท้าย [STOCK.md](STOCK.md)

### วิธี deploy ที่ใช้อยู่ — ด้วยมือ

```bash
git pull
cd worker
npx wrangler deploy
```

**ยังไม่ต่อ Cloudflare Workers Builds กับรีโปนี้** — เคยลองแล้วระบบล่ม อ่านเหตุผลข้างล่างก่อนคิดจะต่อใหม่

### ⚠️ เคยลองต่อ Workers Builds แล้วระบบล่ม

หลังต่อรีโปเข้ากับ build ของ Cloudflare เกิดอาการนี้

```
GET /              200  ขึ้นหน้าเว็บปกติ
GET /api/setup     404  ไม่ใช่ JSON ของระบบ — คำขอไม่ได้วิ่งเข้า Worker เลย
```

**ตัวสคริปต์ Worker ถูกทับหายไป เหลือแต่ไฟล์หน้าเว็บ** และ secret ทั้งสองตัวหายไปด้วย
อาการหลอกตามาก เพราะ service worker มีแคชเปลือกแอปอยู่ หน้าเว็บจึงยังขึ้นสวยงาม
เหลือแค่ "ล็อกอินไม่ได้" ซึ่งชี้ไปทางรหัสผ่านมากกว่าจะชี้ไปทาง deploy

กู้ด้วย `npx wrangler deploy` จากเครื่องแล้วใส่ secret ใหม่

ถ้าจะลองต่อ build อีกครั้ง ต้องตั้งให้ครบสี่ช่องนี้ และ**ทดสอบทันทีหลัง build แรกเสร็จ**

| ช่องที่ต้องตั้ง | ค่า |
|---|---|
| Repository | `ittipat2529/mintra-stock` |
| Branch | `main` |
| **Root directory** | **`worker`** ← ถ้าผิดช่องนี้ build จะไม่เห็น `wrangler.jsonc` |
| Build command | เว้นว่าง — ไม่มีขั้น build |
| Deploy command | `npx wrangler deploy` |

`worker` เป็น root เพราะ `wrangler.jsonc` อยู่ที่นั่น และมันอ้าง `../docs` ออกมาหาไฟล์หน้าเว็บ
`wrangler` ถูกตรึงเวอร์ชันไว้ใน `worker/package.json` พร้อม `package-lock.json`
build จึงได้เวอร์ชันเดิมทุกครั้ง

**สามอย่างที่ต้องเช็คทันทีหลัง build แรก** อย่าเชื่อว่าสำเร็จเพราะหน้าเว็บยังขึ้น

```bash
curl -s https://<worker>.workers.dev/api/setup      # ต้องได้ JSON ไม่ใช่ 404
npx wrangler secret list                            # ต้องมีครบทั้งสองตัว
npx wrangler deployments list                        # ดูว่า build เป็นคนขึ้นจริง
```

ถ้า `/api/setup` ได้ 404 ให้ `npx wrangler deploy` กู้ทันที แล้วถอด build ออก

## ข้อควรรู้

- **รีโปนี้ต้องเป็น private ตลอดไป** `data/users.json` เก็บ hash รหัสผ่านของทีม
- **ความจริงของยอดสต็อกอยู่ใน Durable Object ไม่ใช่ในรีโป** รีโปได้สำเนาคืนละครั้ง
  แลกกันตรงนี้เพื่อให้ยิงบาร์โค้ดได้เร็วและเรียลไทม์
- **ไม่ได้ผูกกับ Shopee/Lazada อัตโนมัติ** คลังต้องยิงตอนแพ็คเสมอ
- **iPhone ยิงด้วยกล้องไม่ได้** ใช้เครื่องยิงหรือพิมพ์รหัสแทน · Android ใช้กล้องได้
- ข้อจำกัดที่เหลืออ่านได้ที่ [STOCK.md](STOCK.md#ข้อจำกัดที่ควรรู้)
